### Safer installs on real computers
Found on a real laptop and in a bug hunt through 1.1.2. If you install from a **Ventoy** USB stick, please use this version.

- **The installer never offers the USB stick it runs from.** On a Ventoy stick (and others that load the ISO from a file), 1.1.2 listed the stick itself as a disk to install on, and erasing it destroyed the stick. Both installers now find the stick through Ventoy's layers and leave it out; the install refuses it even if it is chosen some other way.
- **Erasing a disk works when something on it is in use.** If one of the disk's old partitions was open (mounted by Files, swap, or left from an earlier system), the install stopped at "Formatting" with "is mounted". The installer now turns off and unmounts everything on the chosen disk first, and never formats unless the new partition layout is really in use.
- **Usernames and names that broke the install are caught up front.** A name with `:` `"` `$` or a backquote, or the username `root` (or one the system uses, like `git`), made the install fail at the very end. The name is now cleaned, and such usernames are refused before anything is changed.
- **When an install fails, the installer says so at once and honestly.** It no longer claims nothing was changed after the disk has been erased.
- **Password-free sudo is never left behind,** however an install ends, and the one used briefly after the first start to install AUR apps is removed straight away, even after a power cut.
- **Wi-Fi networks with a "/" in their name** reconnect after installing.

Existing installs get all of this with `anarch update` (the installer fixes only matter for new installs).
